# WhiteListChecker — текущий MVP (v1.0)

## Цель

Android-приложение определяет наблюдаемые признаки режима белых списков мобильного оператора. Оно не утверждает, что белые списки «точно включены»: классификация строится по доступности контрольных сайтов и дополнительной DNS-диагностике.

## Проверка мобильной сети

Даже при включённом Wi‑Fi приложение отдельно получает cellular `Network` через `ConnectivityManager.requestNetwork(...)` и выполняет проверку через него.

Основной маршрут:

1. получить cellular `Network`;
2. проверить настроенные DNS resolver через этот network;
3. разрешить контрольные hostname через custom DNS, а при недоступности resolver — при необходимости через `Network.getAllByName(...)`;
4. выполнить HTTPS target checks через `network.socketFactory`;
5. классифицировать прежде всего по результатам сайтов;
6. использовать DNS только как вторичный диагностический сигнал.

Недоступность отдельных публичных DNS-серверов не должна сама по себе создавать статус `MOBILE_DNS_FAILURE`. UDP/53 timeout/network failure допускает TCP/53 fallback.

## Локальные функции

- ручная проверка;
- редактируемые списки сайтов и DNS;
- история проверок;
- статистика и timeline;
- диагностический отчёт;
- локальные уведомления;
- WorkManager background checks;
- foreground active monitoring;
- RU/EN настройки интерфейса.

## Telegram

Поддерживаются личные уведомления и команды через Worker пользователя:

```text
Android -> user-owned Cloudflare Worker -> user's Telegram bot
```

Это опциональная функция. WhiteListChecker не предоставляет и не требует центральный Worker.

## Что удалено в v1.0

- общий публичный сервис;
- публичный Telegram-бот проекта;
- отправка агрегированных публичных отчётов;
- очередь `pending_public_reports`;
- привязка устройств к общему сервису;
- remote commands через центральный сервис;
- встроенный production URL общего Worker;
- permission приблизительного местоположения, использовавшийся для региона общего сервиса.

## Хранение данных и обновление

Room schema v8 содержит локальную историю, статистику, timeline и очередь личного Telegram relay. Миграция `7 -> 8` при обновлении с `0.10.4` удаляет только устаревшую таблицу `pending_public_reports`.

Пользовательские локальные данные и настройки, не относящиеся к публичному сервису, должны сохраняться при обновлении без очистки приложения.

## Ограничения

- результат является эвристикой по наблюдаемому поведению сети;
- VPN может менять маршрут трафика и остаётся отдельным ограничением;
- custom DNS использует незашифрованный DNS/53;
- WorkManager не гарантирует точное расписание;
- Android может ограничивать foreground service;
- личный Telegram требует собственного Worker и бота пользователя.
