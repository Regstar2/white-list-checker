# Feedback — WhiteListChecker 1.0

## Пользовательский путь

В разделе «О приложении» доступны два действия:

- «Сообщить об ошибке» → `bug_report.yml`;
- «Предложить улучшение» → `feature_request.yml`.

Обе формы открываются только в публичном репозитории `Regstar2/white-list-checker` через системный браузер.

## Авторизация и секреты

Android-приложение не содержит GitHub PAT/OAuth write credential и не создаёт Issue через API. Публикация Issue выполняется самим пользователем на GitHub.

Приложение автоматически передаёт только безопасное значение `BuildConfig.VERSION_NAME` в редактируемый заголовок Issue. Оно не прикладывает автоматически:

- логи;
- `BOT_TOKEN`;
- Relay Secret;
- `chat_id`;
- personal Worker URL;
- пароли;
- signing/keystore data;
- историю или результаты проверок.

Issue Forms дополнительно предупреждают пользователя не публиковать чувствительные данные.

## Формы

`bug_report.yml` запрашивает минимальные данные для воспроизведения: описание, шаги, ожидаемое поведение, версию приложения/Android, устройство и сетевой контекст. Поле диагностики опционально и явно ограничено несекретной информацией.

`feature_request.yml` собирает проблему, предлагаемое улучшение, область продукта и альтернативы.

Blank issues отключены, чтобы основной публичный feedback flow шёл через структурированные формы.

## Ошибки открытия

Если на устройстве нет Activity, способной обработать HTTPS URL, либо Android запрещает запуск Intent, приложение показывает локализованную ошибку и продолжает работать. Feedback не влияет на cellular checker и не блокирует остальные функции.

## GitHub default-branch nuance

GitHub берёт Issue Forms из default branch репозитория. Поэтому новая форма по `?template=bug_report.yml` / `feature_request.yml` полноценно доступна после попадания соответствующих файлов в `main`. До merge можно проверить Android UI и корректность официального URL; после merge требуется повторно открыть обе формы и убедиться, что GitHub показывает именно structured Issue Form.
