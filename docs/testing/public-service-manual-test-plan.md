# Public Service Manual Test Plan

## Public user без приложения

1. Открыть центрального Telegram-бота новым Telegram-аккаунтом.
2. Выполнить `/start`.
3. Нажать «Статус по данным пользователей».
4. Выбрать регион.
5. Выбрать оператора.
6. Повторить status.
7. Проверить, что бот не требует установить Android-приложение.
8. При недостаточной выборке увидеть «Недостаточно независимых данных» или «Свежих данных нет».
9. Загрузить тестовые reports в D1.
10. Проверить consensus enabled, disabled, mixed и fallback window.
11. Убедиться, что ответ содержит disclaimer и не содержит `installationId`/`chatId`.

## Android public sharing

1. Установить приложение начисто.
2. Открыть «Общий сервис».
3. Убедиться, что отправка обезличенных результатов выключена.
4. Выполнить проверку мобильной сети.
5. Убедиться, что public report не создан.
6. Убедиться, что поля URL общего сервиса нет.
7. Проверить, что личный Telegram relay по-прежнему имеет отдельное поле Worker URL на экране уведомлений.
8. Нажать «Определить местоположение автоматически».
9. Отказать в location permission.
10. Проверить понятный fallback ручного выбора региона и города.
11. Выдать approximate location и повторить автоопределение.
12. Подтвердить найденный регион и город либо исправить их вручную.
13. Определить оператора автоматически.
14. Проверить ручной override оператора и возврат в auto mode.
15. Включить «Отправлять обезличенные результаты».
16. Сохранить настройки.
17. Выполнить успешную проверку.
18. Проверить upload и появление результата в aggregate.
19. Смоделировать недоступную cellular network.
20. Убедиться, что недоступность не голосует в public aggregate.
21. Выключить sharing.
22. Убедиться, что pending public queue очищается и новые reports не отправляются.

## Linking

1. В приложении открыть «Общий сервис».
2. Убедиться, что URL общего сервиса не вводится вручную.
3. Нажать «Создать код привязки».
4. В Telegram отправить `/link ABCD-EFGH`.
5. Убедиться, что устройство появилось в `/devices`.
6. Повторно отправить тот же code.
7. Ожидаемо: отказ из-за одноразовости.
8. Отозвать связь из Android.
9. Проверить, что remote access исчез.
10. Создать новую связь и отозвать её из Telegram.

## Remote checks

1. Включить «Разрешить удалённую проверку из Telegram».
2. Не запускать active monitoring.
3. В Telegram нажать «Проверить сейчас».
4. Ожидаемо: устройство offline, нужно запустить активный мониторинг.
5. Запустить active monitoring в приложении.
6. Дождаться heartbeat.
7. Нажать «Проверить сейчас».
8. Проверить состояние ожидания.
9. Проверить Success, Unavailable и Failed responses.
10. Нажать повторно быстрее cooldown.
11. Ожидаемо: отказ по cooldown.
12. Запустить две проверки параллельно.
13. Ожидаемо: вторая получает busy/active command отказ.
14. Остановить service.
15. Дождаться online timeout.
16. Проверить offline response.

## Sharing off/on при remote result

1. Установить `shareReports=false`, `allowRemoteChecks=true`.
2. Выполнить remote check.
3. Проверить приватный Telegram-result.
4. Убедиться, что public aggregate не изменился.
5. Включить `shareReports=true`.
6. Повторить remote check.
7. Проверить, что тот же локальный результат попал в public report queue и aggregate.

## Сети

1. Включить Wi-Fi и мобильные данные.
2. Выполнить обычную проверку.
3. Проверить диагностику: target checks идут через cellular `Network`.
4. Проверить Worker sync/upload: запросы идут через default network.
5. Отключить cellular network.
6. Проверить `UNAVAILABLE` для проверки.
7. Потерять Wi-Fi при доступной default cellular network.
8. Проверить Worker sync.
9. Включить VPN.
10. Проверить диагностику: приложение не обещает гарантированный обход VPN/Private DNS.

## Dual SIM и оператор

1. Проверить устройство с одной SIM: оператор должен определиться по MCC+MNC текущей сети или имени из каталога.
2. На dual-SIM устройстве включить mobile data на SIM 1 и определить оператора.
3. Переключить default data SIM на SIM 2 и повторить определение.
4. Проверить, что приложение не выбирает первую SIM произвольно.
5. Проверить MVNO или неизвестного оператора: при нераспознанном MCC+MNC должен быть ручной fallback.
6. Убедиться, что report JSON содержит `operatorCode`, `operatorSource`, но не содержит phone number, IMSI, IMEI или SIM serial.

## Геолокация и privacy

1. Отключить геолокацию устройства и нажать автоопределение.
2. Проверить состояние ошибки и возможность ручного выбора.
3. Смоделировать недоступность Geocoder, если возможно.
4. Проверить, что координаты отсутствуют в логах, DataStore, Room и report JSON.
5. Очистить город и убедиться, что report отправляется только с `regionCode`.
