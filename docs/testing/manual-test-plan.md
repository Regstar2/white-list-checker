# Ручной test plan — WhiteListChecker

## v0.8.13 — Active monitoring and notification policies

1. Чистая установка: приложение запускается, активный мониторинг остановлен.
2. Разрешение уведомлений выдано: активный мониторинг запускается и показывает постоянное уведомление.
3. Разрешение уведомлений отклонено: запуск активного мониторинга из UI не начинается, пользователь видит ошибку.
4. WorkManager: выбрать 15 минут и policy «Не уведомлять» — результаты сохраняются, уведомлений нет.
5. WorkManager: выбрать policy «После каждой проверки» — после `Запустить проверку сейчас` приходит одно событийное уведомление.
6. WorkManager: выбрать policy «Только при изменении» — недоступность мобильной сети не создаёт ложное уведомление об изменении.
7. Активный мониторинг: выставить интервал 1 минуту, запустить, проверить первую немедленную проверку.
8. В постоянном уведомлении нажать «Проверить сейчас» — параллельная проверка не запускается, результат обновляется.
9. В постоянном уведомлении нажать «Остановить» — сервис останавливается, уведомление исчезает.
10. При включённой фоновой автопроверке запустить активный мониторинг — WorkManager временно отменяется; после остановки восстанавливается.
11. Включить «Уведомлять о восстановлении проверки»: создать переход недоступно → успешно, получить одно уведомление о восстановлении.
12. Включить Telegram-команды, настроить Worker и recipient: `/status` возвращает сохранённый результат.
13. `/check` запускает новую проверку и отвечает результатом в тот же chatId.
14. Команда от постороннего `chatId` игнорируется.
15. Потеря Worker/default network не создаёт поток Android-уведомлений; ошибка появляется в статусе активного мониторинга после нескольких неудач.
16. Перезагрузка телефона: foreground service не запускается сам.
17. Проверить светлую/тёмную тему и увеличенный шрифт на экране автопроверки.

## v0.8.6 — Whitelist-First Statistics UI

1. Обновиться с v0.8.5 — приложение запускается, история и статистика БС на месте.
2. Главный экран — карточка «Статистика»: доступно целей, % доступности, изменений за период; нет total runs / success rate / серии ошибок.
3. Экран «Статистика» — заголовок и блоки про белые списки; нет большой карточки «Проверки» с метриками run.
4. Верх экрана — обновлено, последняя проверка, статус, проверено целей X/Y.
5. Блок «Белые списки» — доступно/недоступно/%, включения/выключения.
6. «Текущее состояние целей» — компактный список без сырых URL.
7. «Последние изменения» — события доступности; пустое состояние при отсутствии событий.
8. График доступности — %; одна точка — компактно + «недостаточно данных для динамики».
9. График включений/выключений — counts, не проценты.
10. Стабильные/нестабильные — при однородных данных нет ложного рейтинга.
11. «Технические данные проверок» — свёрнуто; «Открыть диагностику»; разворот — метрики проверок.
12. Диагностика — блок статистики проверок и rebuild работают.
13. Тёмная/светлая тема, маленький экран — layout читаем.
14. Без сети / DNS timeout — UI не ломается; ошибка не как «выключение БС» в последних изменениях.
15. Перезапуск — данные сохранены.
16. Rebuild в диагностике — whitelist statistics пересчитывается.
