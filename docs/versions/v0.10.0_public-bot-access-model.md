## Текущая версия

`v0.9.3`

## Новая версия

`v0.10.0 — Public Bot Access Model`

## Контекст

Private bot работает для admin. Теперь нужно подготовить модель публичного доступа, но ещё не открывать public beta.

## Проблема

Нельзя просто открыть private bot всем: нужны роли, ограничения команд, public-safe ответы и rate limit.

## Цель версии

1. Добавить TelegramUser model.
2. Добавить роли PUBLIC/TRUSTED_REPORTER/ADMIN/BLOCKED.
3. Разделить public/admin commands.
4. Добавить BotAccessPolicy.
5. Добавить rate limit.
6. Сохранить private admin capabilities.
7. Не включать public beta.

## Входит в версию

- TelegramUser model.
- TelegramUserRepository.
- Роли `PUBLIC`, `TRUSTED_REPORTER`, `ADMIN`, `BLOCKED`.
- BotAccessPolicy.
- Command permissions.
- Public-safe command set.
- Admin-only command set.
- Rate limit по chat id.
- Storage для пользователей.
- Минимальные admin commands для ролей, если scope не слишком большой.
- Тесты access policy.
- `CHANGELOG.md`.
- `docs/versions/v0.10.0.md`, если структура есть.

## Не входит в версию

- Полное публичное открытие бота.
- Массовый анонс.
- Subscriptions.
- Рассылки.
- Карты.
- Личный кабинет.
- Платный доступ.
- Сложную модераторскую панель.
- Автоматическую регистрацию trusted reporters.
- Выдачу raw reports.
- Данные одного устройства.

## Что нужно найти перед изменениями

1. BotCommandRouter из v0.9.3.
2. Admin access check.
3. Где хранить TelegramUser.
4. Где хранить роли/config.
5. Где private commands.
6. Где Worker tests.
7. Где changelog/docs.

## Архитектурный принцип

Role checks должны жить в `BotAccessPolicy`, а не размазываться по каждому handler. Схема: `Update -> UserRepository -> BotAccessPolicy -> CommandRouter -> Handler`.

## Требования к реализации

- TelegramUser fields: telegramUserId, chatId, username если безопасно, firstSeenAt, lastSeenAt, role, isBlocked, requestCount, lastRequestAt, preferredRegion/operator при необходимости.
- PUBLIC может `/start`, `/help`, `/status`, `/region`, `/operator`, `/target` только public-safe.
- ADMIN сохраняет v0.9.3 commands.
- BLOCKED получает короткий отказ.
- Rate limit не должен раскрывать внутренние лимиты подробно.

## Приватность и безопасность

Запрещено сохранять, показывать, отправлять или логировать:

- номер телефона;
- IMEI;
- IMSI;
- точные координаты;
- токены;
- bot token;
- shared secret;
- authorization headers;
- приватные URL и query-параметры с секретами;
- raw reports там, где пользователь должен видеть только агрегаты.

Если поле сомнительное — не включай его в публичный/серверный контракт без явного обоснования.

## Тесты

Добавь или обнови тесты, если инфраструктура проекта позволяет:

1. Новый пользователь получает PUBLIC role.
2. ADMIN может admin commands.
3. PUBLIC не может diagnostics.
4. BLOCKED не получает данные.
5. Rate limit блокирует частые запросы.
6. Public command не возвращает raw reports.
7. Admin command недоступна public user.
8. Unknown user безопасен.
9. Role change работает, если реализовано.
10. Sensitive data не попадает в public response.

Если тесты добавить невозможно без большого рефакторинга:

1. Не тащи новый тяжёлый тестовый стек.
2. Честно укажи это в отчёте.
3. Добавь подробный ручной сценарий проверки.
4. Сохрани код так, чтобы его можно было протестировать позже.

Проверить вручную:

1. Admin выполняет `/status`.
2. Public user выполняет `/start` и `/help`.
3. Public user пытается `/diagnostics`.
4. Public user делает частые запросы.
5. Blocked user пытается использовать бота.
6. Admin меняет роль, если команда реализована.
7. Проверить public response на raw data.
8. Проверить логи.
