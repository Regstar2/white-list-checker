# v0.8.17 — Public service UX and deployment diagnostics

## Цель

Исправить пользовательские проблемы привязки устройства, заменить устаревшее название устройства по умолчанию и сделать рассинхронизацию Android-клиента с production Worker диагностируемой.

## Входит в версию

- кнопка копирования одноразового кода привязки;
- подтверждение успешного копирования в тексте кнопки;
- системное имя Android-устройства как исходное название устройства;
- fallback на модель устройства и затем на нейтральное название;
- миграция старого значения `Мой телефон` при чтении настроек;
- unit-тесты выбора названия устройства;
- JSON-ответ `/health` с ревизией Worker и списком capabilities;
- capability `service-sync` для проверки удалённых команд;
- unit-тест, подтверждающий регистрацию маршрута `service-sync`;
- команда `npm run verify:production` для обнаружения устаревшего Worker;
- новый README на русском и английском языках по общему стандарту проекта.

## Не входит в версию

- изменение алгоритма классификации сети;
- изменение формата public reports;
- изменение D1 schema;
- изменение Telegram webhook contract;
- автоматическое слияние PR или ручное развёртывание Cloudflare Worker;
- выпуск APK или GitHub Release.

## Причина ошибки активного мониторинга

Android вызывает:

```text
POST /api/v1/installations/me/service-sync
```

Маршрут присутствует в исходниках Worker. Ответ production Worker `404 NOT_FOUND` означает, что развёрнутая версия Worker отстаёт от текущего кода репозитория. После слияния и развёртывания текущей версии `/health` должен сообщать revision `2026-08-06-service-sync-v1` и capability `service-sync`.

Проверка production:

```powershell
cd cloudflare\public-service
npm run verify:production
```

```powershell

```

## Ручное тестирование

1. Открыть экран общего сервиса.
2. Убедиться, что поле названия заполнено именем устройства или моделью.
3. Создать код привязки.
4. Нажать кнопку копирования и вставить код в Telegram.
5. Связать устройство с публичным ботом.
6. Включить удалённые проверки и сохранить настройки.
7. Запустить активный мониторинг.
8. Убедиться, что heartbeat обновляется без `404`.
9. Запросить проверку из Telegram и получить результат.

## Критерии готовности

- код привязки копируется одной кнопкой;
- старое стандартное имя не показывается как значение по умолчанию;
- unit-тесты resolver и Worker route проходят;
- production Worker после deploy сообщает актуальную ревизию;
- `npm run verify:production` завершается успешно;
- README.md и README_EN.md имеют одинаковую структуру разделов.
