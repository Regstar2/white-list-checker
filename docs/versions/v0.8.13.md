# v0.8.13 — Active monitoring and notification policies

## Цель

Расширить автопроверку без изменения алгоритма определения белых списков:

- добавить политики уведомлений для WorkManager;
- добавить опциональный активный мониторинг через foreground service;
- хранить доступность последней попытки отдельно от последнего валидного статуса `WHITELIST_ON/OFF`;
- разрешить команды Telegram-бота во время активного мониторинга.

## WorkManager

Интервалы сохранены:

- 15 минут;
- 30 минут;
- 60 минут;
- пользовательский интервал не ниже 15 минут.

WorkManager остаётся приблизительным механизмом. Android может сдвигать время запуска из-за Doze, энергосбережения и ограничений производителя.

Политики уведомлений:

- `NONE` — не уведомлять;
- `EVERY_ATTEMPT` — уведомлять после каждой завершённой попытки;
- `STATE_CHANGE_ONLY` — уведомлять только при изменении валидного статуса `WHITELIST_OFF ↔ WHITELIST_ON`.

Значение по умолчанию — `STATE_CHANGE_ONLY`, чтобы сохранить прежнее поведение существующих пользователей.

## Разделение доступности и статуса

Добавлен отдельный snapshot:

- последняя попытка: `UNKNOWN`, `AVAILABLE`, `UNAVAILABLE`, `FAILED`;
- последний валидный статус белых списков: только `WHITELIST_ON` или `WHITELIST_OFF`.

Недоступность проверки (`NO_MOBILE_INTERNET`, `MOBILE_DNS_FAILURE`, `CELLULAR_NETWORK_UNAVAILABLE`) и техническая ошибка не перезаписывают последний валидный статус.

`PARTIAL_PROBLEM` сохраняется как результат проверки, но не считается валидным переходом между включёнными и выключенными белыми списками.

## Active monitoring

Добавлен `ActiveMonitoringService`:

- запускается только явным действием пользователя из приложения;
- не стартует после установки;
- не стартует из `BOOT_COMPLETED`;
- не запускается из WorkManager;
- использует `foregroundServiceType="dataSync"`;
- показывает постоянное тихое уведомление в канале `active_monitoring`;
- выполняет первую проверку сразу;
- затем ждёт заданный интервал от 1 до 60 минут;
- не запускает параллельные проверки.

При запуске активного мониторинга периодическая WorkManager-задача временно отменяется. После остановки foreground service она восстанавливается, если была включена до запуска.

На Android 15+ система может ограничить длительность `dataSync` foreground service. `Service.onTimeout(...)` останавливает сервис, сохраняет причину остановки и не пытается перезапускаться в цикле.

## Foreground notification

Канал:

```text
active_monitoring
```

Уведомление:

- ongoing;
- low priority;
- `setOnlyAlertOnce(true)`;
- стабильный notification ID;
- действия:
  - Проверить сейчас;
  - Остановить.

Обычные событийные уведомления используют старый канал `whitelist_events` и не заменяют постоянное уведомление.

## Telegram commands

Команды работают только пока:

1. активный мониторинг реально запущен;
2. в настройках активного мониторинга включены Telegram-команды;
3. Telegram настроен через пользовательский Cloudflare Worker relay;
4. `chatId` команды точно совпадает с включённым получателем.

Поддерживаются:

- `/status` — возвращает сохранённый результат, новую проверку не запускает;
- `/check` — запускает новую проверку через общий runner;
- `/help` — показывает доступные команды.

Android по-прежнему не хранит `BOT_TOKEN` и не вызывает `api.telegram.org` напрямую. Polling идёт через Worker endpoint `/tg/getUpdates`.

Для настоящего long polling нужно обновить Worker шаблоном этой версии: он принимает `timeout` в payload и прокидывает его в Telegram Bot API.

## Что не менялось

- Алгоритм `WhitelistStateClassifier`.
- Список проверяемых сайтов.
- Cellular network routing через `Network.openConnection(...)`.
- Telegram relay security model: `BOT_TOKEN` только в Worker secrets.
- Room-схема истории и очереди.
