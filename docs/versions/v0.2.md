# Cursor prompt: Whitelist Checker Android MVP v0.2

Доработай Android-приложение Whitelist Checker с версии v0.1 до v0.2.

Главная цель v0.2: заменить хрупкую проверку “только Google + Yandex” на устойчивую проверку по группам сайтов. Приложение должно проверять несколько внешних и локальных сайтов через мобильную сеть и классифицировать состояние по проценту доступных целей.

Не добавляй Telegram, WorkManager, Room, DataStore, историю, настройки и прочий архитектурный декор. Сейчас нужна только более надёжная логика проверки. Не надо превращать приложение в центр управления интернетом, человечество ещё не заслужило.

## 1. Что уже должно быть после v0.1

```text

```

В v0.2 нужно аккуратно расширить их, а не переписывать всё с нуля ради спортивного интереса.

## 2. Цель v0.2

Приложение должно:

1. Проверять именно мобильную сеть, даже если активная сеть телефона Wi-Fi.
2. Как и раньше, использовать `ConnectivityManager.requestNetwork(...)` с `TRANSPORT_CELLULAR`.
3. Как и раньше, выполнять HTTP/HTTPS-проверки через `network.openConnection(...)`.
4. Не использовать `activeNetwork` для проверки сайтов.
5. Не использовать `bindProcessToNetwork(...)`.
6. Проверять не 2 сайта, а две группы целей:
   - внешние сайты;
   - локальные/условно доступные сайты.
7. Считать количество доступных сайтов в каждой группе.
8. Классифицировать состояние по доле доступных сайтов.
9. Показывать на экране:
   - итоговый статус;
   - количество доступных внешних сайтов;
   - количество доступных локальных сайтов;
   - список всех проверенных сайтов;
   - HTTP-коды;
   - ошибки;
   - время ответа;
   - время последней проверки.
10. Не добавлять Telegram.
11. Не добавлять фоновые проверки.
12. Не добавлять историю.

## 3. Проверяемые группы сайтов

Создай список целей в коде. Пока без настроек и без внешнего JSON.

### FOREIGN-группа

Используй:

```kotlin
Google:
https://www.google.com/generate_204

Cloudflare:
https://www.cloudflare.com

GitHub:
https://github.com

Wikipedia:
https://www.wikipedia.org
```

### LOCAL-группа

Используй:

```kotlin
Yandex:
https://ya.ru

VK:
https://vk.com

Mail.ru:
https://mail.ru

Gosuslugi:
https://www.gosuslugi.ru
```

Важно: YouTube, Telegram и Discord не добавлять в проверку. Они могут быть в чёрных списках, поэтому для определения белых списков они бесполезны.

## 4. Новые модели

Добавь enum:

```kotlin
enum class TargetGroup {
    FOREIGN,
    LOCAL
}
```

Добавь модель цели проверки:

```kotlin
data class CheckTarget(
    val name: String,
    val url: String,
    val group: TargetGroup
)
```

Обнови `SiteCheckResult`.

Было:

```kotlin
data class SiteCheckResult(
    val name: String,
    val url: String,
    val available: Boolean,
    val httpCode: Int?,
    val error: String?,
    val durationMs: Long
)
```

Нужно сделать так:

```kotlin
data class SiteCheckResult(
    val target: CheckTarget,
    val available: Boolean,
    val httpCode: Int?,
    val error: String?,
    val durationMs: Long
)
```

Добавь модель статистики по группе:

```kotlin
data class TargetGroupSummary(
    val group: TargetGroup,
    val availableCount: Int,
    val totalCount: Int
) {
    val availabilityRate: Double
        get() {
            if (totalCount == 0) {
                return 0.0
            }

            return availableCount.toDouble() / totalCount.toDouble()
        }
}
```

Обнови `NetworkCheckResult`.

Вместо отдельных `google` и `yandex` используй список результатов:

```kotlin
data class NetworkCheckResult(
    val siteResults: List<SiteCheckResult>,
    val foreignSummary: TargetGroupSummary,
    val localSummary: TargetGroupSummary,
    val state: WhitelistState,
    val activeNetworkLabel: String,
    val checkedNetworkLabel: String,
    val checkedAtMillis: Long,
    val error: String?
)
```

Если мобильная сеть недоступна, `siteResults` должен быть пустым списком, а summary должны иметь `availableCount = 0`.

## 5. WhitelistState

Оставь enum:

```kotlin
enum class WhitelistState {
    UNKNOWN,
    WHITELIST_OFF,
    WHITELIST_ON,
    NO_MOBILE_INTERNET,
    PARTIAL_PROBLEM,
    CELLULAR_NETWORK_UNAVAILABLE
}
```

Смысл:

```text
WHITELIST_OFF:
внешние сайты доступны, локальные сайты доступны

WHITELIST_ON:
внешние сайты почти недоступны, локальные сайты доступны

NO_MOBILE_INTERNET:
и внешние, и локальные сайты недоступны

PARTIAL_PROBLEM:
состояние не похоже ни на нормальный интернет, ни на БС, ни на полное отсутствие интернета

CELLULAR_NETWORK_UNAVAILABLE:
Android не дал cellular-сеть

UNKNOWN:
начальное/неопределённое состояние
```

## 6. Новый классификатор

Обнови `WhitelistStateClassifier`.

Он должен принимать:

```kotlin
fun classify(
    foreignSummary: TargetGroupSummary,
    localSummary: TargetGroupSummary
): WhitelistState
```

Правила v0.2:

```text
foreignRate >= 0.5 и localRate >= 0.5:
    WHITELIST_OFF

foreignRate <= 0.25 и localRate >= 0.5:
    WHITELIST_ON

foreignRate == 0.0 и localRate == 0.0:
    NO_MOBILE_INTERNET

иначе:
    PARTIAL_PROBLEM
```

Где:

```kotlin
val foreignRate = foreignSummary.availabilityRate
val localRate = localSummary.availabilityRate
```

Порядок проверок важен.

Сначала проверь полное отсутствие интернета:

```text
foreignRate == 0.0 и localRate == 0.0
```

Потом белые списки:

```text
foreignRate <= 0.25 и localRate >= 0.5
```

Потом обычный интернет:

```text
foreignRate >= 0.5 и localRate >= 0.5
```

Потом `PARTIAL_PROBLEM`.

Иначе при нулевой доступности обеих групп можно случайно классифицировать состояние как БС, что было бы диагностика уровня “роутер моргнул, значит вселенная сломалась”.

## 8. MobileSiteChecker

Обнови `MobileSiteChecker`.

Теперь метод должен принимать `CheckTarget`:

```kotlin
suspend fun checkTarget(
    network: Network,
    target: CheckTarget
): SiteCheckResult
```

Требования остаются прежними:

1. Использовать `network.openConnection(URL(target.url))`.
2. Использовать `HttpURLConnection`.
3. Выполнять вне main thread.
4. Сначала пробовать `HEAD`.
5. Если `HEAD` не поддерживается или возвращает код `405`, можно fallback на `GET`.
6. `connectTimeout = 4000`.
7. `readTimeout = 4000`.
8. Считать доступным HTTP-код `200..399`.
9. Сохранять:
   - HTTP-код;
   - ошибку;
   - длительность.

Важно: не использовать OkHttp для проверки сайтов в v0.2. Нам нужно гарантированно выполнять запрос через конкретный `Network`.

## 9. WhitelistCheckUseCase

Обнови `WhitelistCheckUseCase`.

Алгоритм v0.2:

1. Получить label активной сети телефона только для UI.
2. Получить список целей из `DefaultTargetsRepository`.
3. Запросить cellular-сеть через `CellularNetworkProvider`.
4. Если cellular-сеть недоступна:
   - вернуть `NetworkCheckResult` со state `CELLULAR_NETWORK_UNAVAILABLE`;
   - `siteResults = emptyList()`;
   - summaries с нулями.
5. Если cellular-сеть получена:
   - пройти по всем целям;
   - проверить каждую цель через `MobileSiteChecker`;
   - собрать `List<SiteCheckResult>`;
   - посчитать `TargetGroupSummary` для FOREIGN;
   - посчитать `TargetGroupSummary` для LOCAL;
   - классифицировать состояние через `WhitelistStateClassifier`;
   - вернуть `NetworkCheckResult`.

В v0.2 можно выполнять проверки последовательно.  
Если хочешь сделать параллельно через coroutines, можно, но только аккуратно:

```kotlin
coroutineScope {
    targets.map { target ->
        async {
            mobileSiteChecker.checkTarget(network, target)
        }
    }.awaitAll()
}
```

Если делаешь параллельно, обязательно не блокируй main thread.

## 15. Список сайтов

Для каждого сайта показывай:

```text
Google
Группа: Внешние
Статус: доступен / недоступен
HTTP: 204 / —
Ошибка: SocketTimeoutException / —
Время: 320 мс
```

Для групп использовать русские подписи:

```text
FOREIGN → Внешние
LOCAL → Локальные
```

Список можно разделить на два блока:

```text
Внешние сайты
Локальные сайты
```

Это лучше, чем одна куча, в которой потом сам же потеряешься, как обычно в “быстрых MVP”.

## 16. Ошибки

Если отдельный сайт недоступен, это не должно ломать всю проверку.

Правильно:

```text
Google: ошибка SocketTimeoutException
Cloudflare: доступен
Yandex: доступен
Итог: частичная проблема / БС / обычный интернет
```

Неправильно:

```text
Google упал → вся проверка упала
```

Общие ошибки use case показывать только если реально сломалась общая логика, например exception вне проверки конкретного сайта.

## 19. Acceptance criteria

После выполнения v0.2 должно работать так:

1. Телефон подключён к Wi-Fi.
2. Мобильные данные включены.
3. Пользователь открывает приложение.
4. Пользователь нажимает `Проверить мобильную сеть`.
5. Приложение запрашивает cellular-сеть.
6. Приложение проверяет все FOREIGN и LOCAL сайты через cellular `Network`.
7. Приложение показывает:
   - итоговый статус;
   - активную сеть телефона;
   - проверяемую сеть;
   - сколько внешних сайтов доступно;
   - сколько локальных сайтов доступно;
   - подробный список сайтов;
   - HTTP-коды;
   - ошибки;
   - время ответа.
8. Если внешние сайты почти недоступны, а локальные доступны, приложение показывает:
   - `🟠 Похоже на включённые белые списки`.
9. Если обе группы доступны, приложение показывает:
   - `🟢 Белые списки не обнаружены`.
10. Если обе группы полностью недоступны, приложение показывает:
   - `🔴 Мобильного интернета нет`.
11. Если состояние смешанное, приложение показывает:
   - `🟡 Частичная проблема сети`.
12. Приложение не отправляет Telegram-сообщения.
13. Приложение не выполняет фоновые проверки.

## 20. Финальная задача

Доработай проект до v0.2, сохранив рабочую v0.1-логику проверки через cellular-сеть, но заменив проверку двух сайтов на проверку групп сайтов и новый классификатор по доступности групп.

После изменений проект должен компилироваться и запускаться.
