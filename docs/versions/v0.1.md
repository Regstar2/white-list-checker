# Cursor prompt: Whitelist Checker Android MVP v0.1

Создай первую рабочую версию Android-приложения для ручной проверки состояния белых списков мобильной сети.

Нужно сделать именно MVP v0.1, без расширения задачи. Не добавляй Telegram, фоновые проверки, историю, Room, DataStore, настройки, графики и прочую архитектурную гирлянду. Сейчас нужна одна рабочая проверка по кнопке.

## 1. Цель v0.1

Приложение должно:

1. Запускаться на Android.
2. Иметь один главный экран.
3. По кнопке проверять именно мобильную сеть, даже если активная сеть телефона сейчас Wi-Fi.
4. Запрашивать cellular-сеть через `ConnectivityManager.requestNetwork(...)`.
5. Использовать `NetworkCapabilities.TRANSPORT_CELLULAR`.
6. Выполнять HTTP/HTTPS-проверки через полученный объект `Network`.
7. Использовать `network.openConnection(...)`, а не обычный `URL.openConnection(...)`.
8. Не использовать `ConnectivityManager.activeNetwork` для самой проверки сайтов.
9. Не использовать `bindProcessToNetwork(...)`.
10. Проверять два сайта:
    - Google как внешний контрольный сайт;
    - Yandex как локальный/доступный контрольный сайт.
11. Показывать итоговый статус:
    - белые списки не обнаружены;
    - похоже на включённые белые списки;
    - мобильного интернета нет;
    - частичная проблема сети;
    - мобильная сеть недоступна.
12. Показывать детали проверки:
    - активная сеть телефона;
    - проверяемая сеть;
    - статус Google;
    - статус Yandex;
    - HTTP-коды;
    - ошибки;
    - время ответа;
    - время последней проверки.

## 7. CellularNetworkProvider

Создай класс:

```kotlin
class CellularNetworkProvider
```

Ответственность:

1. Получить `ConnectivityManager`.
2. Запросить мобильную сеть через `NetworkRequest`.
3. Использовать:
   - `addTransportType(NetworkCapabilities.TRANSPORT_CELLULAR)`;
   - `addCapability(NetworkCapabilities.NET_CAPABILITY_INTERNET)`.
4. Вернуть `Network`, если cellular-сеть получена.
5. Вернуть ошибку или `null`, если сеть не получена за timeout.

Требования:

- timeout: 8 секунд;
- использовать coroutines;
- можно использовать `suspendCancellableCoroutine`;
- корректно вызывать `unregisterNetworkCallback(...)`;
- не падать при повторном unregister;
- не добавлять `NET_CAPABILITY_VALIDATED` в `NetworkRequest`;
- не использовать `activeNetwork` для проверки сайтов;
- не использовать `bindProcessToNetwork(...)`.

Примерная логика:

```kotlin
val request = NetworkRequest.Builder()
    .addTransportType(NetworkCapabilities.TRANSPORT_CELLULAR)
    .addCapability(NetworkCapabilities.NET_CAPABILITY_INTERNET)
    .build()
```

Если сеть не получена, приложение должно показать:

```text
Мобильная сеть недоступна. Возможные причины: мобильные данные выключены, нет SIM, нет сигнала, оператор или прошивка не дали поднять cellular-сеть параллельно Wi-Fi.
```

## 8. MobileSiteChecker

Создай класс:

```kotlin
class MobileSiteChecker
```

Ответственность:

1. Принимать `Network`.
2. Проверять URL через `network.openConnection(URL(url))`.
3. Использовать `HttpURLConnection`.
4. Сначала выполнять `HEAD`.
5. Если `HEAD` не поддерживается или возвращает ошибку метода, можно сделать fallback на `GET`.
6. Выполнять сетевые операции вне main thread.
7. Возвращать `SiteCheckResult`.

Таймауты:

```kotlin
connectTimeout = 4000
readTimeout = 4000
```

Сайт считается доступным, если:

```kotlin
httpCode in 200..399
```

Ошибки нужно сохранять в поле `error`, например:

```text
SocketTimeoutException
UnknownHostException
ConnectException
SSLHandshakeException
IOException
```

Не скрывай ошибки полностью. Пользователь должен видеть, что именно сломалось, иначе это будет не диагностика, а гадание на `try/catch`.

## 9. WhitelistCheckUseCase

Создай класс:

```kotlin
class WhitelistCheckUseCase
```

Алгоритм:

1. Получить label активной сети телефона только для отображения в UI.
2. Запросить мобильную сеть через `CellularNetworkProvider`.
3. Если мобильная сеть не получена:
   - вернуть `NetworkCheckResult` со state `CELLULAR_NETWORK_UNAVAILABLE`;
   - `checkedNetworkLabel = "Mobile"`;
   - `google = null`;
   - `yandex = null`.
4. Если мобильная сеть получена:
   - проверить Google через `MobileSiteChecker`;
   - проверить Yandex через `MobileSiteChecker`;
   - передать результаты в `WhitelistStateClassifier`;
   - вернуть `NetworkCheckResult`.

Активную сеть можно определять через `ConnectivityManager.activeNetwork` только для подписи:

```text
Wi-Fi
Mobile
Ethernet
Unknown
```

Но сами проверки сайтов должны идти только через полученный cellular `Network`.

Проверки Google и Yandex в v0.1 можно выполнять последовательно.  
Параллельность пока не нужна.

## 15. Acceptance criteria

После выполнения задачи должен работать такой сценарий:

1. Телефон подключён к Wi-Fi.
2. Мобильные данные включены.
3. Пользователь открывает приложение.
4. Пользователь нажимает `Проверить мобильную сеть`.
5. Приложение запрашивает cellular-сеть.
6. Приложение проверяет Google и Yandex именно через cellular-сеть.
7. Приложение показывает:
   - активная сеть телефона: Wi-Fi;
   - проверяемая сеть: Mobile;
   - Google: доступен/недоступен;
   - Yandex: доступен/недоступен;
   - итоговый статус.
8. Если cellular-сеть недоступна, приложение показывает понятную ошибку.
9. Приложение не делает запросы Telegram.
10. Приложение не выполняет фоновые проверки.
