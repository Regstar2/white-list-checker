## Архитектурный принцип

Стабилизация не должна переписывать bot с нуля. Feedback и webhook reliability должны быть отдельными понятными компонентами/моделями.

## Требования к реализации

- Feedback fields: feedbackId, telegramUserId/chatId, createdAt, message, status, category, commandContext, adminNote, closedAt.
- FeedbackStatus: NEW, REVIEWED, ACCEPTED, REJECTED, DUPLICATE, CLOSED.
- FeedbackCategory: BUG, WRONG_DATA, UNCLEAR_RESPONSE, FEATURE_REQUEST, ABUSE, OTHER.
- Webhook должен безопасно обрабатывать unknown update types, edited messages, callback queries, empty messages, long messages, duplicate update, Telegram sendMessage error, storage error.
- Public messages должны быть короткими, без обещаний точности и без technical internals.

## Приватность и безопасность

Запрещено сохранять, показывать, отправлять или логировать:

- номер телефона;
- IMEI;
- IMSI;
- точные координаты;
- токены;
- bot token;
- shared secret;
- authorization headers;
- приватные URL и query-параметры с секретами;
- raw reports там, где пользователь должен видеть только агрегаты.

Если поле сомнительное — не включай его в публичный/серверный контракт без явного обоснования.
