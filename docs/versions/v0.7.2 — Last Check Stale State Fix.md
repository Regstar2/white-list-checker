## Проблема

На главном экране не отображается состояние последней проверки, если последняя проверка была давно.

Это неправильное поведение.

Старая проверка не должна считаться отсутствующей. Она должна отображаться как последняя известная проверка, но с явной пометкой, что данные устарели.

## Цель версии

Исправить отображение последней проверки на главном экране.

После исправления главный экран должен различать:

1. Проверка никогда не выполнялась.
2. Проверка выполняется сейчас.
3. Последняя проверка есть и она свежая.
4. Последняя проверка есть, но она устарела.
5. Последняя проверка завершилась ошибкой.
6. Последняя проверка завершилась ошибкой и уже устарела.
7. Состояние последней проверки не удалось загрузить.

## Входит в версию

Реализовать только bugfix для последней проверки:

1. Найти, где хранится последний результат проверки.
2. Найти, где главный экран получает состояние последней проверки.
3. Найти, где UI скрывает старую последнюю проверку.
4. Исправить логику так, чтобы старая проверка отображалась.
5. Добавить явное stale/outdated-состояние.
6. Показывать возраст последней проверки.
7. Сохранять отображение ошибки последней проверки, даже если она старая.
8. Вынести новые пользовательские строки в ресурсы.
9. Добавить или обновить тесты для логики состояния последней проверки.
10. Обновить CHANGELOG.md.
11. Если в проекте есть docs/versions/, добавить docs/versions/v0.7.2.md.

## Ожидаемое поведение

Главный экран должен показывать одно из явных состояний.

1. Проверка никогда не выполнялась

Если последней проверки нет, показать смысл:

Проверка ещё не выполнялась

UI не должен показывать stale-состояние, потому что данных действительно нет.

2. Проверка выполняется сейчас

Если проверка выполняется в данный момент, показать смысл:

Проверка выполняется...

Running-состояние не должно затираться stale-логикой.

3. Последняя проверка свежая и успешная

Если последняя проверка есть и она свежая, показать смысл:

Последняя проверка: 5 минут назад
Статус: успешно

4. Последняя проверка старая и успешная

Если последняя проверка есть, но она была давно, показать смысл:

Последняя проверка: 3 дня назад
Статус: успешно
Данные устарели

Блок последней проверки не должен скрываться.

5. Последняя проверка свежая и ошибочная

Если последняя проверка завершилась ошибкой, показать смысл:

Последняя проверка: 10 минут назад
Статус: ошибка

6. Последняя проверка старая и ошибочная

Если последняя проверка завершилась ошибкой и была давно, показать смысл:

Последняя проверка: 3 дня назад
Статус: ошибка
Данные устарели

Старая ошибка тоже является последним известным состоянием и должна отображаться.

7. Состояние не удалось загрузить

Если сохранённое состояние повреждено или не может быть прочитано, показать смысл:

Не удалось загрузить состояние последней проверки

Ошибка должна быть обработана явно, а не проглочена молча.

## Главное архитектурное требование

Не вычислять stale/outdated-состояние прямо внутри UI-компонента.

Нужно найти существующую цепочку:

Repository / storage
→ domain / use case
→ ViewModel / state holder
→ UI state
→ главный экран

Если domain/use-case слоя для такой логики уже нет, добавь минимальный отдельный класс с точной ответственностью.

Допустимые варианты названия:

- LastCheckStateResolver
- CheckFreshnessResolver
- LastCheckUiStateMapper

Выбери название, которое лучше соответствует существующей архитектуре проекта.

Не использовать новые названия без смысла:

- LastCheckManager
- LastCheckProcessor
- LastCheckHandler
- CheckHelper
- CheckUtils

## Модель состояния

Нужно добавить или уточнить явную модель состояния последней проверки.

Предпочтительная структура по смыслу:

LastCheckUiState:
- NoCheck
- Running
- FreshSuccess
- FreshFailure
- StaleSuccess
- StaleFailure
- LoadError

Если в проекте уже есть похожая sealed class, enum или data class — используй существующий стиль и не плодить параллельную модель без причины.

Важно:

stale != no data

Устаревшая проверка — это данные, которые есть, но уже не считаются свежими.

## Порог устаревания

Если в проекте уже есть настройка или константа для актуальности данных — используй её.

Если такой настройки нет, добавь понятную константу в подходящее место.

Пример смысла:

DEFAULT_LAST_CHECK_STALE_THRESHOLD_MS

Требования:

1. Не оставлять магические числа прямо в UI.
2. Не дублировать порог в нескольких местах.
3. Порог должен быть легко изменить позже.
4. Порог должен использоваться только через один источник истины.

## Время и тестируемость

Если логика зависит от текущего времени, не зашивать получение времени глубоко внутри метода так, чтобы это нельзя было протестировать.

Предпочтительно сделать сигнатуру по смыслу:

resolveLastCheckState(lastCheck, currentTime, staleThreshold)

или использовать зависимость через clock/time provider, если такой подход уже есть в проекте.

Не делать скрытую зависимость от текущего времени там, где это усложнит тесты.

## UI-требования

Главный экран должен:

1. Показывать блок последней проверки, если данные существуют.
2. Не скрывать блок только потому, что проверка старая.
3. Визуально или текстово отличать устаревшие данные от свежих.
4. Показывать возраст последней проверки.
5. Показывать ошибку последней проверки, если она была.
6. Не ломать отображение проверки, которая выполняется прямо сейчас.
7. Не ломать текущие route/proxy/network/status-блоки.
8. Не перегружать главный экран лишней статистикой.

## Строки и ресурсы

Все новые пользовательские строки вынести в ресурсы.

Например:

или другой механизм ресурсов, который уже используется в проекте.

Плохо:

Нужно использовать ресурсный механизм проекта.

## Ручное тестирование

Проверить вручную на устройстве или эмуляторе:

1. Первый запуск приложения без истории проверок.
   Ожидается: главный экран показывает, что проверка ещё не выполнялась.

2. Выполнить успешную проверку.
   Ожидается: главный экран показывает свежую последнюю проверку.

3. Искусственно создать или подставить старое время последней проверки.
   Ожидается: главный экран показывает последнюю проверку и пометку, что данные устарели.

4. Создать ситуацию, где последняя проверка завершилась ошибкой.
   Ожидается: главный экран показывает ошибочный результат.

5. Сделать ошибочную проверку старой.
   Ожидается: главный экран показывает старую ошибку и пометку устаревания.

6. Запустить проверку прямо сейчас.
   Ожидается: Running-состояние отображается корректно и не конфликтует со stale-состоянием.

7. Перезапустить приложение после старой проверки.
   Ожидается: состояние последней проверки восстанавливается и не пропадает.

8. Проверить главный экран после обновления с v0.7.1.
   Ожидается: существующее последнее состояние не теряется.
