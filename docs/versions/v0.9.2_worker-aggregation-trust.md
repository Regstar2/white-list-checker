## Контекст

Worker уже принимает отчёты. Теперь нужно превратить сырые отчёты в безопасные агрегаты для будущего бота.

## Проблема

Сырые отчёты нельзя показывать пользователям. Нужны дедупликация, trust, freshness и public-safe агрегаты.

## Цель версии

1. Нормализовать входящие отчёты.
2. Дедуплицировать повторы.
3. Считать агрегаты по region/operator/target/route/network/cell, если cell data есть.
4. Считать confidence score.
5. Понижать доверие к старым данным.
6. Не раскрывать raw reports.
7. Подготовить private read endpoints для v0.9.3.

## Архитектурный принцип

Схема: `ReportStorage -> ReportNormalizer -> ReportDeduplicator -> AggregationUpdater -> TrustCalculator -> AggregationRepository -> PrivateReadEndpoints`. Bot logic не добавлять.

## Требования к реализации

- Aggregate keys: `regionHint`, `operator`, `networkType`, `targetId/safeHost`, `routeKind`, time bucket, cell key если безопасно.
- AggregatedStatus: `LIKELY_WORKING`, `LIKELY_BROKEN`, `UNSTABLE`, `STALE`, `INSUFFICIENT_DATA`, `UNKNOWN`.
- Confidence учитывает independent sources, success/failure ratio, age, disagreement и trustLevel.
- Deduplication защищает от повторной отправки одного batch/checkRun/targetResult.
- Source trust: `UNKNOWN`, `NORMAL`, `TRUSTED`, `SUSPICIOUS`, `BLOCKED`.
- Private read endpoints должны требовать secret и не возвращать raw device reports.

## Приватность и безопасность

Запрещено сохранять, показывать, отправлять или логировать:

- номер телефона;
- IMEI;
- IMSI;
- точные координаты;
- токены;
- bot token;
- shared secret;
- authorization headers;
- приватные URL и query-параметры с секретами;
- raw reports там, где пользователь должен видеть только агрегаты.

Если поле сомнительное — не включай его в публичный/серверный контракт без явного обоснования.

## Тесты

Добавь или обнови тесты, если инфраструктура проекта позволяет:

1. Валидный report обновляет агрегат.
2. Повторный report не удваивает статистику.
3. Два разных устройства повышают confidence.
4. Старые данные дают STALE/lower confidence.
5. Противоречивые данные дают UNSTABLE.
6. Мало данных даёт INSUFFICIENT_DATA.
7. BLOCKED source не обновляет агрегаты.
8. Private endpoint требует secret.
9. Aggregates не содержат installationId/raw reports.
10. Diagnostics не раскрывает sensitive data.

Если тесты добавить невозможно без большого рефакторинга:
