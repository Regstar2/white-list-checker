## Контекст

В v0.9.0 появилась безопасная report schema. Теперь нужен минимальный Worker endpoint для приёма отчётов.

## Проблема

Приложение умеет сформировать отчёт, но ещё нет серверной точки, которая принимает, валидирует и сохраняет данные.

## Цель версии

1. Добавить `POST /api/report`.
2. Принимать JSON `ReportBatch`.
3. Проверять schemaVersion, размер payload и auth.
4. Сохранять принятый sanitized report.
5. Добавить health endpoint.
6. Добавить ручную тестовую отправку из Android только при явном включении.
7. Не публиковать данные наружу.

## Входит в версию

- Worker module/project, если его ещё нет.
- `POST /api/report`.
- `GET /api/health`.
- Server-side ReportBatch validation.
- Basic auth: shared secret, HMAC или installation token.

## Архитектурный принцип

Схема: `Android ReportUploader -> POST /api/report -> ReportRequestValidator -> AuthVerifier -> ReportStorage -> response`. HTTP handler, validation и storage не смешивать в один большой файл.

## Требования к реализации

- `POST /api/report` принимает только JSON, проверяет auth, schemaVersion, payload size, batch limits и sensitive fields.
- Ответ success: `accepted`, `reportId`, `receivedAt`, `schemaVersion`.
- Ответ error: `accepted=false`, `errorCode`, `retryable`, безопасное сообщение.
- `GET /api/health` не раскрывает секреты и внутренние таблицы.
- Секреты хранить через env/secrets mechanism, не в репозитории.
- Android отправка выключена по умолчанию; ручная отправка — только из settings/diagnostics.
- Ошибка отправки не ломает check flow и статистику.

## Приватность и безопасность

Запрещено сохранять, показывать, отправлять или логировать:

- номер телефона;
- IMEI;
- IMSI;
- точные координаты;
- токены;
- bot token;
- shared secret;
- authorization headers;
- приватные URL и query-параметры с секретами;
- raw reports там, где пользователь должен видеть только агрегаты.

Если поле сомнительное — не включай его в публичный/серверный контракт без явного обоснования.

## Тесты

Добавь или обнови тесты, если инфраструктура проекта позволяет:

1. Валидный report принимается.
2. Невалидный JSON отклоняется.
3. Неподдерживаемый schemaVersion отклоняется.
4. Запрос без auth отклоняется.
5. Слишком большой payload отклоняется.
6. Sensitive fields не сохраняются.
7. Storage возвращает reportId.
8. Health endpoint работает.
9. Android ReportUploader не отправляет при выключенной настройке.
10. Ошибка Worker не ломает приложение.

Если тесты добавить невозможно без большого рефакторинга:

1. Не тащи новый тяжёлый тестовый стек.
2. Честно укажи это в отчёте.
3. Добавь подробный ручной сценарий проверки.
4. Сохрани код так, чтобы его можно было протестировать позже.

## Критерии готовности v0.9.1

Версия считается готовой только если:

1. POST /api/report работает.
2. Невалидные отчёты отклоняются.
3. Auth работает.
4. Payload size ограничен.
5. Storage сохраняет отчёты.
6. Android отправка выключена по умолчанию.
7. Нет автоматической отправки.
8. Нет Telegram Bot.
9. Нет public API.
10. Нет sensitive data в логах/storage.
11. Проект собирается.
12. CHANGELOG обновлён.
